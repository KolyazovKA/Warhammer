Техническое задание
1. Общая информация
Название проекта Автоматизированный анализ документов с использованием ИИ: от структурирования данных к осмысленному диалогу
2. Функциональные требования
2.1 Основные функции
·	Загрузка и предварительная обработка документов:
·	Поддерживаемые форматы: doc, docx, pdf, md, xls, xlsx
·	Конвертация документов и индексация в векторную базу знаний
·	Поиск по содержимому (ключевые слова и семантика)
·	Ответы на вопросы (вопросно-ответная система, QA)
·	Извлечение сущностей:
·	даты
·	номера пунктов
·	нормативные требования
·	Проверка соответствия требованиям
·	Объяснение найденных нормативов (ссылка на источник)
·	Поддержка короткого диалога (до 3–5 реплик) с сохранением контекста
3. Формат и источник данных
·	Документы хранятся локально на файловой системе
·	Поддержка обновляемой базы нормативной документации
·	Объем: более 50 документов, возможно крупные по объему



4. Платформы и интерфейс
4.1 Каналы доступа
·	Telegram
·	Веб-интерфейс (SPA с чатом)
·	Возможность последующей интеграции в корпоративный портал
4.2 Интерфейс
·	Минималистичный UI:
·	Поле ввода текста
·	Кнопка отправки
·	Отображение сообщений и результатов
·	Поддержка одной пользовательской роли — пользователь
·	Авторизация не требуется на этапе прототипа
5. Технические требования
·	Модельный стек:
·	Open-source LLM через Ollama
·	Допустимо использование API DeepSeek KEY 
·	API KEY DEEPSEEK txt файле sk-011533b41d13463d98a3e558896665b8
·	Архитектура:
·	Поддержка RAG (Retrieval-Augmented Generation)
·	Горячее обновление базы знаний (без перезапуска)
·	Языковой стек: на усмотрение исполнителей, предпочтительно Python
6. Метрики качества и приемка
·	Точность ответов: ≥ 80% (по релевантности в ручной оценке)
·	Полнота извлечения: ≥ 75% (по эталонной выборке)
·	Средняя скорость ответа: до 1 минуты
·	Критичные ошибки:
·	Потеря доступа к знаниям
·	Ошибки в распознавании структуры документов
·	Ответы вне контекста или с недостоверной ссылкой на нормы
 
7. Артефакты
7.1 Аналитики
·	Постановка задачи
·	Описание вводных данных
·	Сценарии использования
·	Документация (произвольная форма)
7.2 Тестировщики
·	Тестовая документация 
·	Описание итогов "предрелизного" тестирования, 
·	Баг-репорты
7.3 Архитекторы
·	Описание архитектуры системы, 
·	Обоснование инструментов, 
·	Блок-схемы, 
·	Пайплайны. 
7.4 Разработчики
·	Чистый, структурированный код, документация
8. Дополнительные требования
·	Поддержка расширения базы знаний (через добавление новых документов вручную или через интерфейс)
·	Возможность логирования:
·	Вопросов пользователей
·	Времени ответа
·	Ошибок при работе с моделью или данными
·	Гибкость в настройке конфигурации моделей, источников и правил обработки
9. Перспективы расширения
·	Поддержка авторизации и ролей (пользователь / эксперт / администратор)
·	Подключение базы истории диалогов
·	Визуализация ответов и контекстных документов
·	Поддержка командной работы (группы пользователей и совместный чат)
10. Приложения и тестовые данные
·	Эталонная выборка из 10–20 вопросов и соответствующих нормативов для оценки качества извлечения
·	Примеры типовых документов
